Advanced Retrieval Techniques

Each of these solves a specific failure. Each costs something. Almost all ship switched off, because on a local machine the cost is seconds per question and you should spend them where they help.

Techniques that are always on

These cost nothing at question time — they are decided when documents are indexed, or are plain index work with no model involved. There is no switch because there is no reason to turn them off.

TechniqueProblem it solvesCost
Hybrid search Meaning-based search misses exact identifiers; word-based search misses paraphrases. Running both covers each other's blind spot. Free
Rank fusion (RRF) Two searches produce scores on incomparable scales. Merging by rank position instead needs no tuning per document set. Free
Structure-aware splitting A passage spanning two pages cannot be cited honestly. Splitting inside page boundaries keeps every citation exact. At ingest
Search small, read big Small passages match precisely but read as fragments. Match on the small one, hand the model the larger passage around it. Free
Budgeted context Overfilling the model's context window causes silent truncation. Measuring first makes overflow impossible. Free
Citation verification Models sometimes cite sources that were never supplied. Every marker is checked; fabrications are flagged. Free

Optional techniques

Each entry below states the problem, the mechanism, when it earns its cost, and its trade-off. Use the filter to narrow the list.

Resolve follow-up references

On by default · 1 call when triggered

The problem. Follow-up questions are mostly grammar. "How does that compare to the control?" contains almost nothing to search for — the subject lives in the previous exchange.

The mechanism. Before searching, the question is rewritten as a standalone one using the recent conversation. It only runs when the question actually looks like a follow-up, so self-contained questions cost nothing.

YOU TYPE

"How does that compare to the control?"

WHAT IS SEARCHED

"How does the 38 nA/cm² chloride transport in the CFTR-KO line compare to the wildtype control?"

Turn off if
You always ask complete, self-contained questions and want every millisecond.
Measured
Without it, the bare follow-up above retrieved only the control values — missing the figure needed for the comparison. With it, both were retrieved.

Rewrite query for retrieval

Off · 1 call per question

The problem. You ask in your words; the document is written in its authors'. A student asking "what makes cells die on purpose" will not match a paper that says "apoptotic pathways".

The mechanism. The model restates your question in the formal terminology a document would use, keeping every specific name and number intact.

Turn on when
You are searching unfamiliar technical material and do not know its vocabulary.
Turn off when
You already know the terminology — your own wording is then better than a rewrite.
Safety
If the rewrite comes back unusable, your original wording is used instead. A bad rewrite is worse than none, so the system is deliberately suspicious of its own output.

Search multiple phrasings

Off · 1 call + 3 embeddings

The problem. Any single phrasing of a question is one arbitrary route into the document. A slightly different phrasing would have found something else.

The mechanism. Three alternative phrasings are generated, each searched independently, and the results merged. A passage that any one phrasing finds convincingly is not buried because the others missed it.

Turn on when
You suspect passages are being missed entirely — especially for comparison questions that need material from several documents at once.
Trade-off
The best single improvement to recall here, at the cost of one call and three embeddings.

HyDE — search by hypothetical answer

Off · 1 call per question

The problem. Questions and answers are written differently. One asks, the other states. Because semantic search compares your text to document text, that mismatch in form pushes them apart even when the topic matches.

The mechanism. The model writes a short passage that plausibly answers your question, and that is used for the semantic search instead of the question. The invented passage need not be factually correct — only its shape and vocabulary matter. It is never shown to you and never used as evidence.

Worth explaining to students

This one reliably provokes "isn't that making things up?" The answer is instructive: the invented text is used only as a search key, never as evidence. It is thrown away once the real passages are found. The distinction between using a generated artefact to search and using it to answer is a genuinely useful concept.

Turn on when
Questions are short and jargon-heavy and plain search returns little.
Note
Applies to semantic search only. Keyword search keeps using your literal words, since invented terms would corrupt exact matching.

Infer document/section filter

Off · 1 call per question

The problem. When you say "in the methods section of the Smith paper", you have narrowed the search yourself — but a plain search ignores that and hunts everywhere.

The mechanism. The model extracts the restriction and applies it as a filter before searching, so only the named document or section is considered.

Turn on when
You routinely name documents or sections in your questions and have several files loaded.
Safety
A filter naming a document that is not loaded is rejected rather than applied — an invalid filter would match nothing and produce a confidently empty answer.
Alternative
The Restrict search to: Documents selector does the same thing manually, with no model call and no ambiguity.

Re-rank retrieved passages

Off · 1 call per question

The problem. Search is good at deciding what is roughly relevant and less good at ordering the top few. The passage that truly answers your question may arrive fourth.

The mechanism. Deliberately retrieve more than needed, then score each candidate against your question directly and keep the best. Retrieval optimises for finding everything; re-ranking optimises for putting the right thing first. They want opposite things, which is exactly why doing both beats doing either harder.

PassageScoreOutcome
The knockout line's measurement10.0Promoted to first
The control line's measurement5.0Kept — useful context
Routine log entries0.0Dropped
Turn on when
The Sources panel shows the right passage present but ranked low. This is the largest single precision gain available.
Pair with
Raising Candidates considered to 20–25 — re-ranking can only promote what retrieval collected.
Two backends
Local LLM scores everything in one call and needs no installation. Cross-encoder is faster and more accurate per query but requires installing sentence-transformers.

Add contextual headers

Off · 1 call per passage

The problem. A passage lifted out of a long document loses what made it meaningful. "The value rose to 12% in the second cohort" is unfindable for a question about a specific drug, because the drug was named three pages earlier.

The mechanism. At indexing time, a sentence of context is written into each passage before it is converted to numbers. The passage's own text is left untouched — only its searchable representation is enriched, so what you see cited remains the document's own words.

Turn on when
Working extensively with one document that relies on pronouns and back-references — which is most academic writing.
Cost
By far the most expensive option. Roughly 150 model calls for a 100-page document, so minutes rather than seconds. Because the index is temporary, this is paid again every session.
Advice
Worth it for a sustained working session. Not worth it for a quick lookup.

Choosing what to enable

Start with everything at its default. When a specific question fails, work through this order — it moves from cheapest to most expensive, and from most to least likely to help.

  1. Check the diagnostics first. If nothing was retrieved, no amount of re-ranking will help.
  2. Move the balance slider. Free, instant, and often sufficient.
  3. Raise passages sent. Also free.
  4. Turn on re-ranking. One call, biggest precision gain.
  5. Turn on multiple phrasings. One call, biggest recall gain.
  6. Add contextual headers. Only when the document itself is the problem, and only for a session you will spend time in.
Measure, don't assume

Retrieval changes are genuinely hard to judge by reading one answer — a change that fixes the question you are testing routinely breaks two you are not. The application ships with an evaluation harness for exactly this reason. On a test corpus it showed one paraphrased question that no plain configuration retrieved; only rewriting, multiple phrasings and re-ranking together found it. That is not something reading a single answer would ever reveal.
