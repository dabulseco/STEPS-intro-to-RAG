Companion app

Libraries: documents that stay between sessions

The main application forgets everything when you close it. The Library app is a second, separate application that keeps a collection of documents on your computer and turns it into a chatbot you can come back to — with its settings and conversations intact.

Which app should I use?

Main app — app.py

Upload, ask, discard. Nothing is written to disk, so it suits sensitive documents and one-off questions. Includes answer evaluation and question templates.

Library app — library_app.py

Build a library once, then chat with it across many sessions. Suits a course's readings or a project's papers — roughly 50 to 500 documents.

Both use the same retrieval engine, so answers are found and cited in exactly the same way. Run the Library app with: 

python -m streamlit run library_app.py

What a library keeps

  • The documents' text and search index — so a library opens in seconds and you can ask questions immediately, without re-uploading.
  • Publication details — title, authors, year, journal and DOI for each document, shown as a table so you can see what the library contains.
  • Chatbot settings — the chat model, perspective and audience, retrieval settings, and your own custom instructions.
  • Conversations — every question and answer, with copies of the passages it cited, so you can resume a chat later.
What it does not keep The original files. The library holds the text extracted from them, which search needs, but not the PDF, Word or PowerPoint file itself. Answer evaluation is not part of the Library app; use the main app for that.

Adding documents

Adding happens in two steps on the Documents tab.

  1. Check. Choose files and a collection. The app reads each file and compares it with what is already in the library. A review table shows the result for every file.
  2. Add. The accepted files are processed one at a time: details are read, the text is split into passages, and each passage is embedded. Each file is saved as soon as it is done, so an interruption loses only the file in progress. Keep the browser tab open until it finishes.

How duplicates are recognised

MatchWhat happens
The exact same fileSkipped automatically
The same text in a different file (renamed or re-saved)Skipped automatically
The same DOIYou choose: skip, replace the existing one, or keep both
The same title and year (no DOI)You choose: skip, replace, or keep both
No text could be read (a scanned PDF)Not added; scanned pages need OCR first

A preprint and the published version of a paper often share a DOI or title but differ in content, which is why those two cases ask you rather than deciding.

Where the publication details come from

Three sources, all on your computer — nothing is looked up online:

  • A DOI printed in the text — the most reliable identifier.
  • Your chat model reading the first page — usually right, but not guaranteed.
  • Properties stored inside the file — accurate for many publisher PDFs, often junk for self-made files.

If a detail is wrong, correct it with Manage a document → Edit details. Your edits always take priority.

Contextual headers

When you create a library you can switch on contextual headers: the chat model adds a sentence to every passage explaining where it sits in its document, which makes retrieval more accurate. It costs one model call per passage — about 75 for a 15-page paper — and applies to the whole library, so it can only be chosen when the library is created.

Turning a library into a chatbot

The Chatbot settings tab holds everything that shapes answers: a name and description, the chat model and its sampling settings, perspective and audience, retrieval settings, and which collections are searched.

Custom instructions let you describe the chatbot's role, for example “You are a tutor for introductory cell biology. Explain terms before using them.” They are added to the app's built-in rules and cannot switch off answering from the documents or the citation checks.

Re-ranking is on by default here In a large library, many passages look similar to a question. Re-ranking asks the model to reorder the best candidates before answering, which matters far more with hundreds of documents than with a handful. It adds some time to each answer and can be switched off.

Conversations

Every exchange is saved as soon as the answer finishes. The sidebar lists conversations newest first; click one to resume it, or start a new chat. As in the main app, the last five exchanges are given to the model so that follow-up questions such as “what about in mice?” make sense.

Each saved answer keeps a copy of the passages it cited, so it stays checkable even after its document is removed from the library. Conversations can be renamed, deleted, or downloaded as HTML.

Where libraries are stored

Each library is a folder inside libraries/ in the application folder. To keep them elsewhere — a larger drive, say — set the RAG_LIBRARY_DIR environment variable before starting the app.

  • Back up a library by copying its folder while the app is closed.
  • Privacy: the folder contains your documents' text and your conversations. It never leaves your computer, and the libraries/ folder is excluded from Git so it cannot be pushed to GitHub by accident.
  • One app at a time: a library can be open in only one running copy of the app. Several browser tabs of the same copy are fine.

Changing a library later

  • Move a document to another collection, or rename a collection — instant, no re-processing.
  • Re-embed with a different embedding model (Library settings) — no re-upload needed, but it takes about as long as adding the documents did. If it is interrupted, the library keeps using the old model.
  • Delete the library — removes the folder, including every conversation. You are asked to type the library's name first.
