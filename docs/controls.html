Sidebar Controls

Every control in the application, grouped as it appears on screen. Ranges and defaults are taken from the code, not from memory.

No controls match that search.

Answer Source

The most consequential setting in the application. It decides whether the model is permitted to draw on anything beyond your documents.

Allow LLM General Knowledge Default: off

Type checkbox · appears only when documents are indexed

Unchecked, the model may answer only from passages retrieved from your documents, and must say so when the answer is not there. Checked, it may add general knowledge, with instructions to label which is which.

Off
Answers are grounded and citable. Some questions get "not found" — which is the honest result, not a malfunction.
On
Fewer refusals, but the boundary between your documents and the model's training data now depends on the model labelling it correctly.
Advice
Leave it off for anything you will act on. Turn it on when you want a concept in a paper explained in broader terms.

Context Settings

These shape the voice of the answer, not its content. They apply to the whole conversation.

Perspective (Who is writing) Default: Scientist

Options Scientist · High School Teacher · Lay Person

Sets the voice the answer is written in — how technical the vocabulary is, whether it reaches for analogies, how it handles uncertainty.

Impact
Style only. It does not change which passages are retrieved, and will not make an answer more or less accurate.
Advice
Pair with Audience deliberately. "Scientist → Middle School Student" produces genuinely different output from "Lay Person → Scientist".
Audience (Who is reading) Default: Scientist

Options Scientist · College Student · High School Student · Middle School Student · High School Teacher · Lay Person

Sets the reading level and how much prior knowledge is assumed. Selecting a school level introduces explanation of technical terms and everyday examples.

Teaching use
Ask the same question at three audience levels and compare. It demonstrates that an AI system has no single "correct" register — the register is a choice someone made.

Model Settings

How the language model generates text. See Model Settings for recommended combinations.

Select Model Chat models only

Type dropdown, populated from your installed Ollama models

The model that writes answers. Embedding models are deliberately excluded from this list — they cannot generate text, and selecting one produces confusing errors.

Larger
Better at following the "cite your sources" instruction and less likely to fabricate citations. Slower.
Smaller
Faster and workable for straightforward lookup. More prone to ignoring instructions.
Advice
A 7–12 billion parameter model is a reasonable starting point on typical hardware.
Temperature 0.0 – 2.0 · default 0.3

Controls randomness. At each step the model has a ranked set of possible next words; temperature decides how strictly it favours the top of that list.

Low (0–0.3)
Focused, repeatable, sticks closely to source wording. Correct choice for document questions.
High (0.8+)
More varied phrasing — and materially more likely to drift from the sources or invent citations.
Advice
0.1–0.3 for document work. High temperature and grounded answers pull against each other.
Top-K 1 – 100 · default 40

Limits how many candidate words the model may consider at each step. Top-K of 40 means it never looks beyond the 40 most likely options.

Low (1–10)
Very constrained. Can read as stilted or repetitive.
High (60+)
Allows unusual word choices, including some that make the text worse.
Advice
Leave at 40. This is the least useful dial here — adjust Temperature instead.
Top-P 0.0 – 1.0 · default 0.9

Also called nucleus sampling. Rather than a fixed count, it keeps the smallest set of candidate words whose combined probability reaches P — so the model considers few options when confident and more when uncertain.

Low (0.5)
Conservative; only high-confidence words.
High (0.95+)
Admits the long tail of unlikely words.
Advice
Leave at 0.9. Top-P and Temperature overlap; changing both at once makes results hard to attribute.
Context Length 256 – 32,768 · default 8,192

How much text the model can hold at once, measured in tokens (roughly ¾ of a word). This must accommodate the system instructions, conversation history, retrieved passages, your question, and the answer being written.

Raising
More retrieved evidence reaches the model. Uses more memory and is slower.
Lowering
Faster, but the evidence budget shrinks and fewer passages are sent.
Advice
Do not lower this to speed up document questions. Roughly 60% of it is the budget for retrieved passages. Turn off optional techniques instead.
Caution
Setting it above what your model supports has no effect — the model ignores the excess.

Retrieval Settings

Embedding Model Required for document search

Typical nomic-embed-text · mxbai-embed-large

The model that converts passages and questions into numeric representations for semantic search. It is a different kind of model from the chat model and must be installed separately: ollama pull nomic-embed-text.

Without one
Documents can be uploaded and read but not searched. The application says so plainly rather than answering from general knowledge while appearing to read your files.
Changing it
Invalidates the index. Vectors built by one model are meaningless to another, so documents must be processed again.
Advice
nomic-embed-text is fast and sufficient. Larger embedding models cost ingest time for modest gains.
Clear Vector Store Button

Discards the search index and the loaded documents. The index is held in memory only, so it also clears itself when you close the application — this button is for clearing it deliberately, such as before handing the machine to someone else.

After clearing
Strict mode has nothing to answer from and will decline until you process documents again.
Privacy
Nothing was written to disk at any point, so nothing needs deleting from disk.

Retrieval Tuning

Appears once documents are indexed. These change which passages are found — none of them costs an extra model call, so they are free to experiment with.

Semantic ↔ Keyword balance 0.0 – 1.0 · default 0.5

Weights the two search methods against each other. 1.0 is meaning-only, 0.0 is exact-wording-only, 0.5 treats them equally.

Toward keyword
Better for part numbers, gene names, statute references, defined terms — anything where the exact string matters.
Toward semantic
Better for conceptual and paraphrased questions where you do not know the document's wording.
Advice
Leave at 0.5 unless a specific question is failing. Measured on a test corpus, keyword-only missed every paraphrased question while balanced search found them.
Passages sent to the model 1 – 15 · default 5

How many of the best-ranked passages are placed in front of the model as evidence.

More (8–15)
Better for broad questions ("summarise the findings") that draw on several parts of a document. Uses more of the context window.
Fewer (2–3)
Better for narrow factual lookup. Less irrelevant material to distract the model.
Advice
5 suits most questions. Raise it for synthesis and comparison; lower it if answers wander.
Candidates considered up to 40 · default 12

How many passages survive the merge and are available for the final selection. If re-ranking is on, this is the pool it scores.

Higher
Gives re-ranking more to work with — a passage buried at rank 15 can still be promoted. Costs little without re-ranking.
Advice
12 is fine by default. Raise to 20–25 when using re-ranking; that combination is where it pays off.
Candidates per index 5 – 50 · default 20

How deep each of the two indexes searches before their results are merged. Applies equally to the semantic and keyword sides.

Higher
Casts a wider net, so a passage that only one method ranks well still enters the merge. Slightly slower.
Lower
Faster on very large document sets, at the cost of recall.
Advice
20 is a sensible default. Raise it if you suspect relevant passages are being missed entirely rather than merely ranked low.
Restrict search to: Documents Default: all

Limits searching to the documents you select. This is metadata pre-filtering: the restriction is applied before the search runs, not by discarding results afterwards.

Use for
Asking about one paper when several are loaded, or excluding a document you know is irrelevant.
Caution
Filter too narrowly and the answer is limited to that document — which can look like the information is missing when it is simply out of scope.
Generate follow-up questions On · costs 1 model call

After each answer, suggests three follow-up questions you can click to ask.

Cost
One additional model call per answer — often several seconds on local hardware.
Advice
Genuinely useful when exploring an unfamiliar document. Turn it off when you know what you are looking for and want speed.

Document Controls

Process Documents Button · PDF, DOCX, PPTX · 200 MB per file

Extracts text, splits it into passages, and builds both search indexes. A progress bar shows the embedding stage, which is the slow part.

Scanned PDFs
Contain images, not text. Nothing can be extracted; the application detects this and warns you at upload rather than failing quietly later. Run such files through OCR first.
Document length
Does not limit answer quality. Retrieval finds the relevant passages wherever they sit, so a 500-page manual works as well as a 2-page memo.
Add contextual headers Off · 1 model call per passage

Before indexing, writes a sentence of surrounding context into each passage, so that a passage full of vague references stays findable. "The value rose to 12% in the second cohort" becomes searchable as being about the specific study it belongs to.

Benefit
Substantially better retrieval on documents that rely on pronouns and back-references, which is most academic writing.
Cost
The most expensive option here. A 100-page document is roughly 150 passages, so roughly 150 model calls — minutes, not seconds. Because the index is temporary, this is repaid every session.
Advice
Worth it for a document you will question extensively in one sitting. Not worth it for a quick lookup.
Preview Document Content · Inspect Indexed Chunks Diagnostic

Preview shows the raw extracted text. Inspect shows the actual passages retrieval searches over, with page numbers, detected sections and sizes.

Use when
An answer misses something you are certain is in the document. Check here first — it separates an extraction problem from a search problem, which need completely different fixes.
Where to start

Leave everything at its default and use the application normally. Defaults were chosen to be correct for most questions. When something specific fails, change one setting, ask the same question again, and compare — changing several at once makes it impossible to know which one helped.
